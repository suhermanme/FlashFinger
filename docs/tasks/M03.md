## Engine design

`TypingEngine` lives in `src/domain/typing/` with zero React/DOM/audio/storage dependencies. State transitions follow the lifecycle from DESIGN_SPECIFICATION §3.2: `idle → preparing → ready → running ↔ paused → finalizing → completed/aborted/interrupted`. The first accepted character in `ready` auto-transitions to `running`.

### Command processing

`processCommand(EngineCommand)` accepts four command kinds:

- **character**: Compares typed grapheme against target, applies correction policy (advance fills + advances; strict stays at position), updates counters, records in `EditLedger`, and returns `accepted` + `progress` deltas.
- **delete**: Finds the last non-empty buffer position, checks correction window boundary (512 graphemes), updates `backspaces` counter and `retainedCorrect`/`retainedErrors`, and returns `corrected` + `progress` deltas.
- **clock**: Advances the monotonic clock via `tick(nowMs)`, updates `activeElapsedMs`, and returns a `progress` delta.
- **pause**: Toggles `running ↔ paused`, returns `progress` deltas.

Character/delete in non-running states (except `ready` auto-start) return `rejected` deltas with reason `not-editable`. Past-target input returns `rejected` with reason `past-target`. Timed sessions check `isDeadlineReached()` per input.

### TextBuffer

`TextBuffer` uses `Intl.Segmenter('en', { granularity: 'grapheme' })` via the `segmentGraphemes()` helper to split target text into correct Unicode grapheme clusters. Handles ZWJ emoji (👩‍💻), regional indicator pairs (flags 🇮🇩), decomposed combining marks (e + U+0301), and CJK. The buffer is a sparse array with `undefined` for untyped positions. Cursor advances on correct characters; correction policy determines cursor advancement on incorrect characters.

### EditLedger

`EditLedger` implements a bounded circular buffer with `MAX_CORRECTION_HISTORY=512`. Each `record()` call appends a `CheckpointEdit` and the sequence is monotonic. `toSnapshot()` returns the bounded history for snapshot serialisation.

### Metric formulas

`calculateMetrics(MetricInput)` implements DESIGN_SPECIFICATION §4.1 canonical formulas:

| Formula | Implementation |
|---|---|
| Gross CPM | `60 × A / T` |
| Gross WPM | `12 × A / T` |
| Adjusted WPM | `12 × R / T` |
| Attempt accuracy | `100 × C / A` |
| Output accuracy | `100 × R / (R + retainedErrors)` |

Returns `null` when denominators are zero. `computeSample` guards `windowMs <= 0`. `isEligibleForBest` requires ≥15 active seconds. `calculateDailyAggregate` pools sessions.

## Grapheme segmentation correction (2026-09-20T22:00:00Z)

The initial implementation used `[...text]` to split target text into grapheme clusters.
This was found broken for multi-codepoint Unicode sequences:

- ZWJ emoji (👩‍💻): `[...text]` splits into 3 pieces (woman + ZWJ + laptop)
- Flag (🇮🇩): `[...text]` splits into 2 pieces (regional indicators)
- Decomposed é (e + U+0301): `[...text]` splits into 2 pieces

**Fix:** `TextBuffer` now uses `Intl.Segmenter('en', { granularity: 'grapheme' })`
via a new `segmentGraphemes()` helper function. All grapheme segmentation is
centralized in this function for consistency and testability.

**Verification tests added** (11 new tests in Suite 19):

| Test | Verifies |
|---|---|
| ZWJ emoji target length and cursor | 👩‍💻 = 1 grapheme, accepted as correct, cursor=1 |
| ZWJ emoji deletion | One backspace removes entire cluster |
| ZWJ emoji wrong input | '👩' ≠ '👩‍💻' → error |
| Flag target length and cursor | 🇮🇩 = 1 grapheme |
| Flag partial input | '🇮' ≠ '🇮🇩' → error |
| Flag deletion integrity | Delete flag, retype, surrounding graphemes intact |
| Decomposed é = 1 grapheme | e+U+0301 accepted as single unit |
| Decomposed vs precomposed | 'e\u0301' ≠ 'é' (U+00E9) → error |
| Decomposed é deletion | One backspace removes both code points |
| Mixed grapheme sequence | ASCII + ZWJ + flag + combining all count correctly |
| Mixed deletion from end | 3 deletes remove combining é, flag, then only 'a' remains |
